# EXCEPTION, and it is a distribution blocker, not a chore. EVERY published
# macOS arm64 wheel of this package - 4.8.1.78 through 5.0.0.93, headless and
# not - bundles an FFmpeg built --enable-gpl, linking libx264/libx265 (GPL-2.0)
# and self-reporting "GPL version 3 or later". A closed-source app cannot be
# distributed against it, and upstream's README claim that "all wheels ship
# with FFmpeg licensed under the LGPLv2.1" is verifiably false for macOS.
# Nothing we ship even calls those encoders - x264/x265 are encode-only and the
# only avc1 caller (model/engine/overlay.py) is not in the frozen bundle - so this is
# purely about what sits in the DMG. Do NOT delete the dylibs: they are eager
# load commands and cv2 will not import. The fix is a source build against an
# LGPL FFmpeg, and this line must be pinned to that wheel once it exists.
# Full evidence, route and effort: ffmpeg-lgpl (not published). Guard: app/desktop/check-gpl.py.
#
# THAT WHEEL NOW EXISTS, and it is not on PyPI - build it:
#     app/desktop/scripts/build-lgpl-opencv.sh   # -> app/desktop/build/wheels/
#     .venv/bin/pip install --force-reinstall --no-deps \
#         app/desktop/build/wheels/opencv_python_headless-*.whl
# Pinned to the version that build reproduces; a plain `pip install -r` gets the
# PyPI wheel at the same version, which is the GPL one. Check with:
#     strings -a .venv/lib/python3.14/site-packages/cv2/.dylibs/libavcodec.*.dylib | grep license
# and never keep `opencv-python` (the non-headless one) installed beside it: it
# carries its own GPL FFmpeg into the bundle.
